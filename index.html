What is a Process?
● ~15 minutes

A process is a program in execution. A program sitting on a disk is just a file of instructions. When it is loaded into main memory and the CPU starts carrying out its instructions, the operating system (OS) treats it as a process and starts managing it.

💾 Program

A passive set of instructions stored in secondary storage. It does nothing on its own and uses no CPU time.

⚙️ Process

An active instance of a program that is being executed. It has its own memory space, its own current position in the code and its own set of resources (files, devices).

Characteristics of a process
  • It has a unique process ID (PID).
  • It is always in one state (e.g. ready, running, blocked).
  • It has a priority that can affect when it runs.
  • It has its own allocated memory and resources.
  • Its progress is recorded by the program counter and register values.
  • The same program can run as several processes at once — e.g. two browser windows.

The OS keeps a PCB for every process. It holds everything the OS needs to stop a process and later restart it exactly where it left off.
Why is process management needed? A modern computer may have hundreds of processes but only a few CPU cores. A single core can execute only one process at a time. The OS must create and end processes, share out the CPU and memory, keep processes from interfering with each other, and switch between them so quickly that they appear to run at the same time. This is called multitasking.

2
Process States
● ~20 minutes

From the moment it is created to the moment it ends, a process is always in exactly one state. The state tells the OS what the process is doing and whether it can be given the CPU. The OS records the state in the process's PCB.

StateWhat it means
NewThe process is being created. The OS sets up its PCB and memory.
ReadyThe process is in main memory and could run straight away — it is only waiting for the CPU. Ready processes wait in the ready queue.
RunningThe process's instructions are being executed by the CPU. On a single-core CPU only one process can be running.
Blocked
(also called Waiting)		The process cannot continue until an event happens, such as an input/output (I/O) operation finishing or a key being pressed. Giving it the CPU would be pointless.
Terminated
(also called Exit)		The process has finished or been stopped. The OS removes its PCB and frees its memory and resources.
The process state diagram
The six transitions
  • New → Ready: admitted to the ready queue.
  • Ready → Running: the scheduler dispatches it to the CPU.
  • Running → Ready: its time slice ends, or a higher-priority process needs the CPU.
  • Running → Blocked: it must wait for I/O or another event.
  • Blocked → Ready: the I/O or event has completed.
  • Running → Terminated: it finishes or is stopped.
Why have states at all?

States let the OS see at a glance which processes can use the CPU (Ready) and which cannot (Blocked). The CPU is never wasted on a process that is just sitting and waiting for a slow device.

While one process is blocked waiting for the printer, another ready process can be running — so the CPU is kept busy.

Watch out: there is no arrow from Blocked straight to Running. When a blocked process's I/O finishes, it goes back to Ready and waits to be chosen by the scheduler like everyone else.

3
Scheduling
● ~10 minutes

Scheduling is how the OS decides which ready process runs next on the CPU and for how long. The part of the OS that makes this decision is the scheduler. It follows a set of rules called a scheduling algorithm.

Why is it needed? There are usually far more ready processes than CPU cores. Without a fair, planned way of sharing the CPU, some processes would never run, the computer would feel slow and unresponsive, and the CPU would sit idle while processes waited for I/O.

What a good scheduler tries to achieve
Keep the CPU busy
Maximise CPU utilisation — never leave it idle if work is waiting.
High throughput
Complete as many processes as possible in a given time.
Fairness
Give every process a reasonable share of CPU time.
Fast response
Interactive programs should react quickly to the user.
Short waiting time
Minimise the time processes spend in the ready queue.
No starvation
Every process should eventually get the CPU.
Pre-emptive scheduling

The OS can take the CPU away from a running process — for example when its time slice ends or a higher-priority process arrives — and move it back to Ready. Good for responsiveness.

Non-pre-emptive scheduling

Once a process has the CPU it keeps it until it finishes or blocks for I/O. Simpler, with fewer switches, but one long process can hold everybody up.

Context switch: every time the CPU moves from one process to another, the OS saves the running process's program counter and registers into its PCB, then loads the saved values of the next process. This takes time during which no useful work is done, so too many switches waste CPU time.
Useful measures: burst time = how much CPU time a process needs; waiting time = time spent in the ready queue; turnaround time = time from arriving to finishing. You will use these to compare algorithms.

First-Come, First-Served (FCFS)

The ready queue is a simple first in, first out queue. The process that arrived first gets the CPU and runs until it finishes or blocks. FCFS is non-pre-emptive.

Waiting times: A = 0, B = 6, C = 9. Average waiting time = (0 + 6 + 9) ÷ 3 = 5. Notice that C needs only 1 unit of CPU time but waits 9 units behind A — this is called the convoy effect.

Benefits
  • Very simple to understand and implement
  • Low overhead — few context switches
  • No starvation: every process eventually runs
Drawbacks
  • Short jobs can wait a long time behind long ones
  • Average waiting time is often high
  • Poor for interactive systems — one process can hog the CPU
Round Robin (RR)

Each process is given a fixed amount of CPU time called a time slice (or quantum). If it has not finished when its time slice ends, it is pre-empted and sent to the back of the ready queue. If it finishes early, the next process starts straight away. Round robin is pre-emptive. Below, the time slice is 2.

Shortest Job First & Multi-level Queue
● ~15 minutes
Shortest Job First (SJF)

When the CPU becomes free, the scheduler picks the ready process with the shortest burst time (the least CPU time needed). The chosen process then runs to completion, so SJF is normally non-pre-emptive. Using the same processes as before (A = 6, B = 3, C = 1):

B
A
0
1
4

Waiting times: C = 0, B = 1, A = 4. Average waiting time = (0 + 1 + 4) ÷ 3 ≈ 1.67 — much lower than FCFS's 5 for exactly the same work.

Benefits
  • Gives the lowest possible average waiting time
  • High throughput — lots of short jobs finish quickly
Drawbacks
  • The OS must know or estimate burst times in advance, which is often impossible
  • Starvation: a long job may wait forever if short jobs keep arriving
Going further: a pre-emptive version, shortest remaining time, switches to a newly arrived process if it needs less time than the one currently running.
Multi-level Queue

Instead of one ready queue, the ready processes are split into several separate queues, each for a different type of process. Each queue has its own priority and can use its own scheduling algorithm. A process is placed in one queue when it is created and stays there.

A common rule is fixed priority: the scheduler only takes from Queue 1 when Queue 0 is empty, and only from Queue 2 when Queues 0 and 1 are both empty.

Benefits
  • Important processes are dealt with first
  • Each type of process gets an algorithm that suits it
  • Interactive programs stay responsive
Drawbacks
  • Low-priority queues can suffer starvation
  • Inflexible — a process cannot move to a different queue
  • More complex to set up and manage
Going further: a multi-level feedback queue lets processes move between queues — for example, a process that has waited a long time can be promoted to a higher queue to prevent starvation.

✓ Summary — Topic 1.2.3: Process Management
Process: a program in execution, with its own PID, state, priority, memory and resources. The OS stores its details in a Process Control Block.
Process states: New → Ready → Running → Terminated, with Running → Ready (time slice ends), Running → Blocked (waits for I/O) and Blocked → Ready (I/O completes).
Scheduling: the scheduler decides which ready process gets the CPU and for how long, aiming for high utilisation, fairness, fast response and no starvation. It can be pre-emptive or non-pre-emptive.
FCFS: runs processes to completion in arrival order. Simple with no starvation, but short jobs can wait behind long ones.
Round robin: each process gets a fixed time slice, then goes to the back of the queue. Fair and responsive, but adds context-switching overhead.
SJF & multi-level queue: SJF picks the shortest job for the lowest average wait; a multi-level queue serves separate priority queues in order. Both risk starvation.
